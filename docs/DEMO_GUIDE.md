# CAN-7USAT Ground Station Demo Guide

## Overview

This project is a browser-based ground station dashboard for CAN-7USAT telemetry. This version upgrades the original repository with a more complete aerospace-style mission control interface, improved mock telemetry behavior, safer command handling, clearer telemetry analysis, and a repeatable demo flow.

The ground station now includes:

- Mission Control
- Engineering Telemetry
- Flight Analysis
- System Logs
- Mission Config
- Mock mission reset and demo flight profile
- Operator-safe command confirmation
- Real / Derived / Simulated data tagging

## Runtime Stack

Frontend:

- React
- Vite
- TypeScript
- WebSocket telemetry client

Backend:

- FastAPI
- WebSocket telemetry stream
- Mock telemetry generator
- REST endpoints for status, history, command handling, and mock reset

## How to Run

Open two PowerShell terminals.

### Terminal 1 - Backend

Run:

    cd "D:\CAN-7USAT-Ground-Control-Backend-master\CAN-7USAT-Ground-Control-Backend-master\backend"
    .\.venv\Scripts\activate
    python run.py

Backend runs at:

    http://localhost:8000

Useful checks:

    Invoke-RestMethod "http://localhost:8000/api/health"
    Invoke-RestMethod "http://localhost:8000/api/status"

### Terminal 2 - Frontend

Run:

    cd "D:\CAN-7USAT-Ground-Control-Backend-master\CAN-7USAT-Ground-Control-Backend-master\frontend"
    npm run dev

Frontend runs at:

    http://localhost:5173

## Demo Flow

1. Open http://localhost:5173
2. Go to Mission Control.
3. Click RESET SESSION.
4. Confirm reset.
5. Watch the mission progress through:

    PRE_FLIGHT -> BOOST -> COAST -> APOGEE -> DESCENT -> LANDED

6. Open Engineering Telemetry to inspect packet values, attitude data, packet integrity, GPS, and filtered acceleration.
7. Open Flight Analysis after landing to review apogee, time to apogee, max velocity, acceleration, landing position, and state transitions.
8. Open System Logs to verify reset, WebSocket, and flight-state events.
9. Open Mission Config to review real, derived, and simulated data sources.

## Mock Reset Endpoint

The frontend reset button calls:

    POST /api/mock/reset?profile=demo

This restarts the backend mock mission from T+0 without manually restarting the backend server.

The demo profile provides a short full mission cycle with boost, coast, apogee, descent, and landing phases.

## Data Source Labels

REAL values are received directly from the backend telemetry packet or backend status.

Examples:

- altitude_m
- velocity_ms
- quaternion values
- gps_lat
- gps_lon
- checksum_xor
- backend uptime
- websocket clients

DERIVED values are calculated by the frontend from real packet values or status data.

Examples:

- roll / pitch / yaw
- filtered derived acceleration
- packet rate
- packet loss
- max altitude
- max velocity
- state transition counts

SIMULATED values are generated by the backend mock profile or used for demo/runtime clarity.

Examples:

- mock flight profile
- mock reset endpoint
- simulated data rate in mock mode
- demo flight sequence

## Major Improvements Made

### Frontend Redesign

The original dashboard was redesigned into a more serious aerospace-console interface inspired by mission-control and rocket simulator references. The UI now uses a black-and-white technical style, denser telemetry panels, clearer grid layout, and more professional operator-focused pages.

### Mission Control

Mission Control now includes:

- Flight state timeline
- Altitude, vertical velocity, max altitude, and max velocity readouts
- Flight timer
- Altitude, velocity, and filtered acceleration charts
- Attitude visualizer
- Quaternion / Euler attitude panel
- GPS and map panel
- Diagnostics panel
- Event log and warning console
- Safety-gated command panel

### Backend Demo Profile

A backend mock reset flow was added so the mission can be restarted from the frontend. The demo profile creates a complete mission sequence for presentation and testing.

### Engineering Telemetry

Engineering Telemetry now shows:

- Primary flight channels
- Packet integrity
- Attitude matrix
- GPS / position data
- Altitude, velocity, and filtered acceleration profiles
- Real / Derived / Simulated labels

### Flight Analysis

Flight Analysis now provides:

- Apogee
- Time to apogee
- Max vertical velocity
- Max derived acceleration
- Flight duration
- Landing coordinates
- Flight profile chart
- State transition table

### System Logs

System Logs now includes:

- Command events
- State transitions
- WebSocket events
- Warning console
- Packet loss visibility
- Link and packet-rate status

## Notes for Reviewers

This project intentionally avoids adding fake unsupported sensor channels as real telemetry. New values are labeled as real, derived, or simulated depending on their source. The goal of the redesign is to improve clarity, demo reliability, and operator usability while staying within the backend telemetry data available.
